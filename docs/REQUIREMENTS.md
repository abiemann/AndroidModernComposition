# Requirements map

This maps every area from the original Android-practice table to concrete source, verification, and remaining study/production work. Names joined by “or,” “some roles,” or “tools vary” describe ecosystem alternatives; installing all of them into one journal would not demonstrate coherent design. The implementation selects one primary approach and labels alternatives explicitly.

**Implemented** means executable source exists. **Verification** identifies the relevant tests or manual exercise, not an automatic claim they have all run. Consult [TODO](../TODO.md) for executed results.

The selected testing scope follows the preference for method-level tests. Routine CI uses JVM tests, lint, builds, and documentation checks. Functional UI automation is excluded; non-UI Android/server integrations and performance exercises remain available for manual study.

## Alternative-stack exercises

These are explicitly **not implemented integrations**. Each should preserve the same behavior tests rather than adding an unused dependency.

| Technology mentioned in the original table | Exercise and acceptance criterion |
| --- | --- |
| Hilt / Dagger | Replace Koin only at composition boundaries; keep constructor tests; validate worker and navigation ViewModel scopes. |
| MVI reducer library | Extract a reducer if UI transitions become complex; demonstrate a simpler state model and equivalent behavior, not duplicate MVVM state. |
| RxJava | Adapt a hypothetical existing stream at a repository boundary; verify disposal/cancellation and error semantics before exposing Flow. |
| GraphQL | Implement a second `RemoteNotes` adapter and schema; preserve explicit versions, operation IDs, tombstones, and conflict semantics. |
| gRPC / Protocol Buffers | Define typed RPC/messages and map gRPC statuses into the same retry/auth/rejection model; test protocol compatibility. |
| OpenAPI | Derive a machine-readable specification from [API](API.md), validate server contract tests against it, and generate a client in an isolated branch. |
| NoSQL | Replace server persistence while retaining atomic conditional writes and durable operation replay. Explain the resulting consistency/transaction guarantees. |
| Kotest / Mockito / MockK | Compare one existing behavioral test with another tool; keep fakes for stateful repository semantics where they clarify the test. |
| Crashlytics / Sentry | Add a consent-aware provider, scrub payloads, upload release mappings, trigger a controlled nonfatal diagnostic, and verify ingestion/retention. |
| A/B platform / SQL / Snowflake | Define exposure, assignment, outcome, guardrail, and retention semantics; analyze synthetic consented events, then label findings as synthetic. |
| Bitrise / Buildkite / Fastlane / Runway / Azure Pipelines | Reproduce the same checks and protected release stages; avoid maintaining multiple unvalidated pipelines for this one app. |

## Primary references

Architecture follows the separation, lifecycle-aware state, and repository principles in [Android architecture recommendations](https://developer.android.com/topic/architecture/recommendations) and [offline-first guidance](https://developer.android.com/topic/architecture/data-layer/offline-first). Background execution uses [WorkManager's persistent-work model](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started). Credential keys use the [Android Keystore system](https://developer.android.com/privacy-and-security/keystore). The [Compose compiler setup](https://developer.android.com/develop/ui/compose/setup-compose-dependencies-and-compiler) and [Gradle compatibility matrix](https://docs.gradle.org/current/userguide/compatibility.html) explain toolchain version constraints. Dependency pins in this repository are an intentional tested set, not a claim that every pin is the newest available release.
